What each platform does when an utterance's language ≠ the voice's language. Decided 2026-08-07/08; every outcome row below is pinned by a unit test.

The rules in one breath

Detection runs once per utterance, never per chunk, with the shared 81 KB trigram table (identical bytes on Android and CLI). An explicit language always wins over detection. Kokoro auto-detects by default. Kitten is English unless an alias opts into Auto-detect — then a Kokoro voice of the detected language wins when one is installed and the route may switch voices; otherwise Kitten reads the detected language's espeak phonemes itself: accented, "not good but not unusable — better than nothing" (Max). Pocket is always English (it doesn't phonemize through espeak at all). The CLI never switches engines — you named the engine on the command line.

2 · Android — what a detected language does

Alias setting first: Kokoro's (empty) means Auto-detect (its default); Kitten offers exactly English (US) and Auto-detect (opt-in); Pocket is pinned English. An explicit code skips everything below. Then the route decides whether the voice may move:

espeak codes: en→voice's region (en-us/en-gb) · es→es · fr→fr-fr · it→it · pt→pt-br · ja→ja · hi→hi · zh→en-us (no espeak Mandarin in our stack — real Mandarin needs a Chinese Kokoro voice, whose own lexicon path handles it).
